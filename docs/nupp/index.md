# The Nupp rewrite

Tecs is being rewritten in Nupp against Rust services, and the two
implementations are in the tree at once. Their documentation is in the tree at
once too, and this directory is the Nupp half.

## Two sites, until the Teal tree goes

The Teal implementation's reference is generated by Tealdoc, which reads
declarations out of `src/**.tl` and appends them to the pages under
`docs/modules/`. It resolves a module only through `src/<name>.tl` or
`src/<name>/init.tl`, so it cannot read a Nupp declaration and cannot project a
Nupp module's API onto a page. Teaching it to would mean a second Nupp parser
inside a tool whose whole job is about to end.

So the Nupp half is rendered by Nupp's own documentation generator, from the
same docblocks the compiler checks:

```bash
cargo xtask nupp docs        # Render the Nupp site into out/nupp-docs
cargo xtask nupp docs-check  # Render it into a scratch directory and gate it
```

Every page in this directory is published by both sites. The Nupp site carries
it with the generated reference for the module it describes. The Tealdoc site
carries the prose alone, because it has no reference to append, which is why a
page here is written to stand on its own rather than as the bare heading a Teal
module page is.

`cargo xtask docs-check` is unchanged and still holds the Teal pages to
`src/tecs/init.tl`. It accepts a page in this directory rather than rejecting
one, and it makes no claim about it beyond what it claims about any guide page:
that it carries a description, avoids an em dash, and links only to things that
resolve.

The two collapse into one when the Teal implementation is deleted. At that
point `docs/` is the Nupp site, `tlconfig.lua` goes with Tealdoc, and this page
goes with them.

## Contracts sit on the declaration

On the declaration, in Nupp, exactly as the Teal tree writes it on a Teal
declaration. A module opens with a long `--[[ ]]` comment holding its
introduction and its cross-symbol constraints; every public function, record and
field carries a `---` docblock with `@param` and `@return`. The generator reads
those, so a signature has no second copy to drift from.

A page here holds what a declaration cannot: a workflow that crosses modules,
an architecture decision, a comparison. It does not restate a signature.

## The reference covers every landed module

Everything the `headless` target builds, which is every `src/**.nupp` module.
The generated reference covers the whole module tree, so a module that has
landed has its contracts published whether or not anyone has written a guide
page for it yet.
